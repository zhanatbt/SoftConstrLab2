Конвертирование пакета из KRSU в PCMS2 [+]
Конвертирование пакета из KRSU в EJUDGE [+]

Любая пара из четырёх форматов (KRSU, CATS, PCMS2, EJUDGE) тоже поддерживается.


Как запустить

Нужен .NET 9 SDK.

1. Распаковать архив (или клонировать репозиторий).
2. Открыть командную строку в папке, где лежит PackageConverter1.sln.
3. Собрать:
       dotnet build PackageConverter1
   Исполняемый файл появится в PackageConverter1\bin\Debug\net9.0\PackageConverter1.exe
4. Запуск:
       PackageConverter1\bin\Debug\net9.0\PackageConverter1.exe [FORMAT_FROM] [FORMAT_TO] [PACKAGE_1] [PACKAGE_2]

   Либо без отдельной сборки:
       dotnet run --project PackageConverter1 -- [FORMAT_FROM] [FORMAT_TO] [PACKAGE_1] [PACKAGE_2]

Форматы: KRSU, CATS, PCMS2, EJUDGE.
PACKAGE_1 - исходный пакет (папка или .zip), PACKAGE_2 - итоговый пакет.
Если PACKAGE_2 оканчивается на .zip, результат будет архивом, иначе папкой.
Если итоговая папка уже существует и не пуста, программа остановится, чтобы ничего не затереть.

Примеры (из папки с PackageConverter1.sln):
(Заранее скопировал и поместил в директорию проекта папку с названием "5295" с архивами)
    dotnet run --project PackageConverter1 -- PCMS2 KRSU 5295\PCMS2\sample out\sample_krsu
    dotnet run --project PackageConverter1 -- KRSU PCMS2 5295\KRSU\A out\A_pcms2
    dotnet run --project PackageConverter1 -- CATS KRSU 5295\CATS out\cats_krsu
    dotnet run --project PackageConverter1 -- EJUDGE KRSU 5295\EJUDGE\sample out\ejudge_krsu


Как устроено

Каждый формат читается в общую модель задачи (папка Model), а из неё записывается
в нужный формат. Для каждого формата есть один читатель (Readers) и один писатель
(Writers), поэтому отдельные конвертеры для каждой пары форматов не нужны.
FormatConverter получает читатель и писатель по названию формата и ничего
не знает о конкретных форматах. Список форматов собирается в Program.cs.

SOLID:
- каждый класс отвечает за одно: читает один формат, пишет один формат или копирует файлы;
- чтобы добавить формат, нужно написать новый класс и добавить его в Program.cs,
  остальной код не меняется;
- читатели и писатели взаимозаменяемы через интерфейсы IPackageReader и IPackageWriter;
- чтение и запись - разные интерфейсы, формат можно поддержать только в одну сторону;
- FormatConverter зависит от интерфейсов, а не от конкретных классов.


Что не переносится (программа выводит предупреждения)

- В примерах части файлов тестов нет на диске (их создаёт генератор, а в EJUDGE
  папка tests пустая). В описании нового пакета такие тесты остаются, программа
  пишет, сколько файлов не найдено.
- В CATS нет ответов к тестам (их выдаёт решение), поэтому из CATS выходные
  файлы не создаются. Условие CATS в формате STML не переносится.
- Чекер: если есть .exe, берётся он, иначе исходник (его нужно скомпилировать).
  Встроенный чекер KRSU $fc в CATS заменяется на std.strs, в PCMS2 и EJUDGE
  аналога нет.
- В PCMS2 у групп нет баллов, поэтому в KRSU они будут нулевыми.
- В EJUDGE баллы за отдельные тесты записываются как группы по одному тесту.
